ABSTRACT
The project EventHub – Smart Event Registration Website is a web-based event regis-
tration system developed to provide a simple and organized way for participants to view event
information and submit their registration details online. The website combines an event land-
ing page with a structured registration form and an administrative panel for managing submitted
registrations.
The public-facing interface provides event information such as the event introduction, sched-
ule, speakers, venue information and registration option. The registration module collects per-
sonal and academic information, allows the participant to select an event category and optionally
upload a student identity document. Client-side and server-side validation is used to reduce in-
complete or invalid submissions. Duplicate email registration is also checked before a record
is stored.
The backend is implemented using PHP and MySQL. Registration records are stored in re-
lational tables, while event categories are maintained separately so that they can be managed
from the administrative panel. Each registration is assigned a registration ID and initially re-
ceives a pending status. The admin panel provides facilities for viewing, searching, filtering,
editing and deleting registrations, managing categories and changing registration status. Status
changes can also trigger email notifications to the participant.
The project uses HTML, CSS, Bootstrap, JavaScript, PHP, MySQL and PHPMailer. The
interface is designed to be responsive, while the backend uses sessions, prepared statements and
password hashing for important administrative operations. Sensitive credentials and personal
registration records are deliberately excluded from this report. The report focuses on the design,
implementation, working flow and documented functionality of the project.

CHAPTER 1
Introduction
1.1
Project Description
EventHub is a web-based event registration website designed around a technology-event land-
ing page and an online registration workflow. The main purpose of the project is to replace a
basic manual registration process with a structured digital form through which participants can
submit their details and event category online.
The website has two main parts. The first is the public interface, where visitors can read
about the event, view the schedule and speakers, see basic venue information and open the
registration form. The second is the administrative interface, where authorized administrators
can manage registrations and event categories.
The registration workflow collects the participant’s full name, email, mobile number, gen-
der, college, department, academic year, address and selected event category. A student ID
document can be uploaded optionally. After validation, the information is inserted into the
database with a generated registration ID and a pending status. The system also supports email
communication related to registration and status updates.
1.2
Project Objectives
The main objectives of the project are:
• To develop a user-friendly online event registration interface.
• To organize participant information in a structured MySQL database.
• To validate important registration fields before storing data.
• To prevent duplicate registration using the participant’s email address.
• To provide an administrative panel for registration management.
• To support pending, approved and rejected registration statuses.
• To provide email confirmation and status-update communication.

1.3
Project Scope
The scope of EventHub covers the complete registration cycle from viewing event information
to administrative processing of a submitted registration. The system supports event categories
such as Workshop, Seminar, Conference, Webinar and Hackathon through database records.
The administrator can add, edit and remove categories subject to registration dependencies.
The project is suitable for college events, workshops, seminars, conferences and similar
activities where participant information needs to be collected and reviewed. The current imple-
mentation is focused on registration management rather than payment processing, ticket gener-
ation or a multi-event calendar platform.
1.4

2. Event Administrators: Authorized users who manage registrations, categories and par-
ticipant status.
3. Event Coordinators: Staff members who may use the administrative information for
reviewing and organizing participants.

Design and Implementation Constraints
The implementation has several practical constraints. Registration data depends on database
availability, while email delivery depends on valid SMTP configuration. Uploaded files are

is designed for a single event-oriented workflow rather than a complete commercial event-
management platform. The report therefore documents only the functionality that is present in
the supplied implementation.
Sensitive configuration values, database credentials, SMTP credentials, passwords, per-
sonal registration records and uploaded identity documents are not reproduced in this report.

3.2.2
Duplicate Registration Check
Before inserting a new record, the application checks the submitted email address using a pre-
pared statement.
$check = $conn->prepare(
"SELECT id FROM registrations WHERE email = ?"
);
$check->bind_param("s", $email);
$check->execute();
if ($check->get_result()->num_rows > 0) {
$_SESSION['error'] = "Email already registered";
}
3.2.3
Registration Storage
After validation and category lookup, the application generates a registration identifier and
stores the record with an initial pending status.
$reg_id = 'REG' . str_pad(time() % 100000, 5, '0', STR_PAD_LEFT);

Administrative Status Update
The admin panel permits only the three statuses defined by the application: pending, approved

if ($id > 0 && in_array($status,

3.3
Security and Privacy Considerations
The implementation uses prepared statements for several database operations, session-based ac-

CHAPTER 4
Results and Discussion
4.1
Functional Results
The supplied implementation provides a complete registration-oriented workflow connecting
the public website, PHP processing layer and MySQL database. The registration form contains
personal, academic and event-selection fields, while the backend validates the submitted infor-
mation before processing it. The application also checks for an existing registration using the
participant email address.
After a valid registration is stored, a registration identifier is generated and the participant
is shown a success message. The implementation also contains email functions for participant
confirmation, administrator notification and later status updates. These functions are integrated
with the registration and administrative status workflow.
4.2
Administrative Results
The administrative interface provides a dashboard with total, pending, approved and rejected
registration counts. Recent registrations can be viewed from the dashboard. The registration-
management page supports searching by participant name, email or registration ID and filtering
by status. Individual registrations can be viewed and edited, while deletion is also supported.
The category-management interface allows the administrator to add and edit event cate-
gories. A category with existing registrations is protected from deletion by the application
logic. The admin profile and password pages provide basic account-management operations.
4.3
User Interface Results
The public interface uses a dark navigation and hero section, card-based content blocks, event
schedule tabs, speaker cards, contact information and a registration call-to-action. Bootstrap
provides responsive layout behavior, while custom CSS controls the visual appearance. Media
queries adjust the hero section and information layout for smaller screens.
The registration interface is divided into clear sections for personal information, academic

4.4
Validation and Error Handling
The registration module checks for required fields, valid email format, ten-digit mobile num-
ber, selected gender, college, department, year, address, event category and terms acceptance.
Optional student-ID uploads are restricted to JPG, PNG or PDF formats and to a maximum file
size defined by the application.
The application uses session messages to display success or error information after form
processing. If an email is already registered, the user is returned to the registration page with
an appropriate message rather than creating another record.
4.5
Discussion
The project demonstrates how a relatively small web application can combine frontend design,
server-side processing, database management and email communication in one workflow. The
separation between participant-facing pages and the administrative panel provides a clear divi-
sion of responsibilities.
At the same time, the implementation is intentionally focused on the core registration pro-
cess. Features such as online payment, QR-based entry passes, automated certificate gener-
ation, calendar synchronization and a multi-event scheduling engine are outside the current
scope. These can be considered for future development rather than being presented as existing
functionality.

CHAPTER 5
Conclusion and Future Scope
5.1
Conclusion
EventHub – Smart Event Registration Website was developed as a practical web application
for organizing event registration through a digital interface. The project brings together a
participant-facing event page, a structured registration form, server-side processing, a MySQL
database and an administrative management panel.
The implementation demonstrates the use of HTML, CSS, Bootstrap, JavaScript, PHP and
MySQL in a single project. Important registration operations such as validation, duplicate
checking, document upload, registration-ID generation and status management are handled
through the application. The admin panel further provides tools for reviewing and maintaining
registration records and event categories.
The project also provides experience with sessions, prepared database statements, password
hashing, file handling and SMTP-based email communication. Overall, the system provides a
clear foundation for a small-scale college or institutional event registration workflow.
5.2
Future Scope
The following improvements can be considered in future versions:
• Add secure online payment integration for paid events.
• Generate downloadable registration receipts or QR-based entry passes.
• Add automated certificate generation after event completion.
• Introduce a participant login area for viewing registration status.
• Support multiple independent events with separate dates, venues and capacity limits.
• Add registration capacity control and automatic wait-list handling.
• Add richer reports and export options such as CSV/PDF for administrators.
